## 一页总览

```
                 Phase 0 基线（低压，只统计不判定）
                          │  产出各长度桶 p99
                          ▼
   absolute 门限 ◄── 系数 × 基线 p99 ──► baseline_relative 按桶门限
   （业务契约）                        （跨引擎自适应）
                          │
   递增并发 ramp ──────────┤
   （闭环，排队→拒绝两阶段）│
                          ▼
   每级请求三分类：A1 失败 / A2 达标 / A3 慢但成功
                          │
              SLA=(A2+A3)/N     SLO=A2/N
              「接得住」        「接得好」
                          ▼
   连续前缀规则 ──► 质量容量（SLA∧SLO 双达标的最高连续前缀）
                    = 生产并发建议的唯一基准
```

## 关键方法论决策记录

以下决策均在代码中固定，修改前需先读对应章节：

| # | 决策 | 理由（详见） |
| --- | --- | --- |
| D1 | 请求三分类 A1/A2/A3，不用单一成功率 | 分钟级时延下"成功但慢"与失败等效 [01] |
| D2 | SLA 与 SLO 分开陈述，生产建议只认**质量容量** | 排队型过载会给出 SLA 100% 而 SLO 归零的假象 [01] |
| D3 | SLA 目标恒为固定配置值，**不动态化** | SLA 是业务契约，目标随表现浮动则验收失去意义 [03] |
| D4 | SLO 门限可换尺子，但**禁用本次运行的分位数定标** | 循环论证：门限随压力抬升 → SLO 恒等于目标 → 指标永真 [03] |
| D5 | 基线只统计分位数，不对 A2/A3 判定 | 基线是尺子的来源，再拿它判达标会形成循环 [03] |
| D6 | 长度分桶判定，A3 按桶归因 | TTFT 与 prompt 长度强相关，全局单门限混淆"长度差异"与"排队劣化" [03] |
| D7 | 被放弃的在途请求单列 `aborted`，不进任何比率 | 否则最慢的请求被静默丢弃，造成存活者偏差 [04] |
| D8 | 容量判定用**连续前缀**而非全局最大值 | 防中间级别抖动造成的高估 [02] |
| D9 | 分位数用最近秩定义，不插值 | 门限来源不应被个别样本插入"平均"拉偏 [04] |
| D10 | 样本不足的级别/桶显式降级并标注，绝不静默 | 不可信的统计量比没有统计量更危险 [03][04] |
| D11 | 配置值与实际值分开记录（阶段时长、基线时长） | 自适应延长是真实行为；只记配置值会让报告与日志对不上 [02][03] |
| D12 | 时延用客户端视角（含建连），但 `connect_ms` 单独可见 | 用户感知的是全部等待；跨部署对比时需要能扣除客户端开销 [01][04] |
| D13 | 时间戳（`sent_at`）取**发出时刻**，不取发现时刻 | 否则超时/放弃请求会把吞吐窗口推晚，RPS 被系统性低估 [04] |
| D14 | 样本量门限按"判定粒度"区分：级用 `min_samples_per_stage`，桶用 `baseline_min_samples` | 门限按桶解析，按桶反推的总量需求远大于按级；共用一把门限会让 baseline_relative 在默认配置下失效 [03] |
| D15 | 水位语义定位为**服务端水位的黑盒可观测投影**，不实现资源级水位计算 | 压测是黑盒客户端，看不到 KV/slot/GPU；内部资源水位归服务端 Prometheus，加权复合水位归 Worker 限流器 [05] |
| D16 | 预测模型按 stage 分组交叉验证 + 残差 ECDF 校准 + 包络守卫，A3 样本必须入训 | 同级样本随机划分会让验证指标虚高；排队时延不满足高斯假设，分位数与通过率须由折外残差经验分布给出；膝点区只有 A3 样本，剔除即删除模型最需学习的区域 [06] |
| D17 | A1 按归因家族拆分（拒绝族/超时族）驱动过载形态解读，分类规则不变 | Router 配无限队列时过载无 429/529、只投影为客户端超时（仍是 A1、仍拉低 SLA、仍触发硬水位），但治理动作与拒绝型完全相反（给队列设上限 vs 扩容/调准入）；家族由 `fail_kinds` 现场推导，不落库、`--report-only` 一致 [05][01] |
| D18 | SLA/SLO 是**实测边界**而非人工设定值：A3 拐点 = 质量/SLO 边界、A1 拐点 = 可用性/SLA 边界，人工只提价值目标（可用性几个 9 + 质量退化预算系数），门限默认来源改为 baseline_relative | 工具的目的是把服务等级测出来，不是拿实测值对照固定目标；口径定义（SLA=A2+A3、SLO=A2）决定拐点归属；absolute 保留为业务契约验收模式（跨次可比），此时拐点含义变为契约违约起点；拐点与目标容量两种严密度分开陈述，质量容量 ≤ 拐点 [01] |
| D19 | **测量与场景分析解耦（一次采集、两套分析）**：一次运行全量采集延迟与吞吐两侧基础指标，在线/容量分析消费同一批数据各出报告；不存在场景模式开关，差异只在负载形状配置与报告选择（`report.kinds`） | 容量（批量）场景不是第二种控制循环而是第二种分析；"批量不测延迟"会无谓丢弃零成本数据，还使 `--report-only` 无法事后补报告；共享一份 runner/metrics/store 的收益（同库两分析、跨次可比）大于复制两套栈 [07] |
| D20 | **容量承诺用吞吐单位且必须带负载坐标**：SLA=RPM@A1 膝点、SLO=全量 TPS@同膝点（input+output，分解保留为诊断量），μ(负载水平, 输入长度) 是函数不是标量；有效吞吐只计成功请求（`ok_rps`），含失败的 `rps` 分列标注 | 容量分析不消费质量维度，A3 恒 0 使比率 `SLA=SLO` 退化、失去分辨力；全部快速失败时 `rps` 反而最高（fast-fail 刷吞吐），不拆列会把失败速率当容量 [07][01] |
| D21 | **容量读数取峰值而非膝点值（诚实口径）**：容量读数级 = 膝点级及低压各级 `ok_rps` 的峰值所在级；排队型饱和时膝点级即峰值（与 `ok_rps(c*)×60` 文档口径一致），硬拒绝型服务在膝点级即坍塌时取低压峰值并在结论中显式说明；容量面 `req_conc` 与读数级同源，`--capacity-plan` 的"所需并发"是参考并发 | E2E 逼出的修正：硬拒绝型服务（有界队列 + 429/503）膝点级大部分请求被拒，`ok_rps` 远低于低压峰值，把坍塌值当容量会系统性低估服务能力；取峰值是统计诚实原则（AGENT.md）的要求，代价是报告必须说明读数级与膝点级的关系 [07][01] |
| D22 | **容量面坐标升为 `(L_in, L_out)` 二维**：输出长度纳入坐标（`ThroughputPoint.output_len`），不靠"每次运行钉死常量"锁定；仅单 `(L_in, L_out)` 组合可入面，混合档位诚实降级（报告明说本次无可入面的膝点事实）；merge 按 `(L_in, L_out)` 单元格覆盖更新，不同 cell 共存；`--capacity-plan` 双坐标查询（双线性插值，缺省取最小输出档并提示显式指定） | 人工压测案例实证 RPM 对输出长度近似反比（同部署同并发差 2.97×）；钉死常量下不同 `L_out` 的 μ 混进同一张面且 npz 无从分辨（D21 遗留缺口）；容量是向量不是标量 [07] |
| D23 | **软退化（全程无 A1）服务以平台期第二读数收场**：峰值位于梯度上限且末级边际增幅 < 5%（`plateau_margin`）、末级 `ok_rps` 不低于峰值 5% 差值带 → 给"范围内饱和读数"（峰值 `ok_rps`×60，明确标注**非膝点**）并入容量面（`a1_family=none, origin=plateau`）；否则维持"未确定容量膝点"的诚实降级并附平台判定的排除理由 | 案例 B 组已饱和（吞吐走平 + 延迟爆炸）却被 `knee=None` 当成未饱和，`--capacity-plan` 出现盲区；读数只对已测负载范围与超时预算有效（D25 协同） [07] |
| D24 | **批量路径两道数据质量闸门（Little's Law + 时延恒等式）**：闭环下 `rps×平均E2E≈并发`、`E2E≈TTFT+TPOT×(输出−1)`，偏差 > 15% 记入吞吐报告诊断行，只警告不阻断；仅由 `report.kinds` 含 `throughput` 的路径调用，不进在线报告、不进 `store.py` | 案例 C@64 污染行靠人眼发现（TTFT 比更低负载还慢 2.3× + 守恒式缺口 22%）；两校验输入均已存在于 `StageStats` 与请求明细，近乎免费，且与在线逻辑零交叉（隔离纪律 R4） [07][04] |
| D25 | **容量读数必须与 `timeout_s` 同印**：膝点 = 服务拒绝（A1 拒绝族）**或** 客户放弃（A1 超时族，位置由客户端 `timeout_s` 框定）；吞吐报告头与 `--capacity-plan` 均同印超时预算与读数来源（膝点实测 / 软退化平台估计） | 案例显示同一服务容量读数随超时预算差 2~8×，不同预算下数字不可比；不印预算的容量数字不可解释 [07][01] |

## 背景阅读（外部理论来源）

本工具的方法论不是凭空发明的，下列领域的公开研究与实践是它的基础：

- **SRE 实践**：Google SRE 体系中 SLI/SLO/SLA 的划分、error budget 思想，
  是"SLA 是契约、SLO 是目标、两者分开管理"的来源。
- **排队论**：利用率 ρ→1 时等待时间按 ~1/(1-ρ) 发散（M/M/1 及其扩展），
  是"过载先表现为排队、后表现为拒绝"以及容量拐点形状的理论解释；
  Little's law（L = λW）解释了闭环低压级别样本产出速率为何受单请求 E2E 限制。
- **大模型推理服务研究**：vLLM 的 continuous batching 与 PagedAttention、
  Splitwise / DistServe / Mooncake 的 PD 分离（prefill 与 decode 分离部署）、
  Sarathi-Serve 的 chunked prefill——解释了 PD 分离下的时延结构
