# PD 分离推理服务质量（SLO/SLA）评估报告

- 测试时间：2026-11-03 10:00:00 ~ 2026-11-03 10:30:00
- 被测服务：`http://127.0.0.1:8123`（`/v1/chat/completions`，模型 `default`）
- 判定门限：TTFT ≤ 2.0s，TPOT ≤ 50.0ms（absolute 模式，所有长度桶统一）
- 人工价值目标（只作约束，非门限来源）：可用性 SLA ≥ 99.9%（3 个 9）、质量 SLO ≥ 95.0%；SLA/SLO 的边界值由本次压测实测产出（见结论第一条）
- 压测模式：closed，压力级：[2, 4, 8, 16]

## 一、结论

- **实测质量边界（SLO 边界 / 质量拐点）= 并发 32**（该级失败 A1=30/60 直接拉低 SLO 至 0.00%，A3=0）：质量崩塌由失败驱动（拒绝或客户端超时），而非排队慢化，与可用性边界重合：该并发之内请求在尺子内完成且不失败，之上质量不再保持。
- **实测可用性边界（SLA 边界 / A1 拐点）= 并发 32**（该级 A1=30/60，SLA=0.000%）：该并发之内服务接得住，之上开始出现失败。
- 两个拐点回答“退化从哪里开始”；下方质量容量结论（并发 8）是人工价值目标口径的保守子集（目标门限严于拐点门限），推荐生产并发以它为准。判定尺子为人工设定的业务契约门限，拐点即契约违约起点。
- **在并发 ≤ 8（已测试梯度内）时，服务同时满足 SLA ≥ 99.9% 与 SLO ≥ 95.0%，该并发为质量有效容量（SLA=100.000%，SLO=100.00%）。**
- **建议生产并发上限设为 8（留 20% 余量则取 6）。**
- 3 个 9 口径（SLA ≥ 99.9%）对应的最高并发为 8（SLA=100.000%，该点 SLO=100.00%）。
- SLO（95.0%）口径对应的最高并发为 8（SLO=100.00%）。
- 水位边界：软水位投影（BUSY，排队预警线）自并发 32 起；硬水位投影（OVERLOAD，熔断线）自并发 32 起；SLA 水位（业务目标口径）= 并发 8（与质量容量一致）。
- 并发 16 起 SLA 跌破 99.9%（96.667%），请求全部成功但时延超标（A3=2），过载表现为排队而非拒绝。
- 水位判定的补充说明：
- 硬水位投影（并发 32）未晚于软水位投影（并发 32）：压力跳过排队区直接触发硬水位（拒绝或客户端超时），Router 准入策略可能较激进，或配置了无限队列。

## 二、基线剖析与判定门限

本次使用 absolute 门限（固定值，跨次运行可比，适合作为业务验收契约）。若需自动适配不同推理引擎/模型规模，可改用 `slo.target_mode=baseline_relative`，由 Phase 0 低压基线的 p99 × 系数生成各长度桶的门限。

## 三、测试方法

1. 以闭环方式逐级提升并发（每级含预热与稳压两段，预热数据不计入统计）。
2. 每个请求按预置的长度分布合成（prompt 长度 / 输出长度均按权重采样），并附加唯一前缀以规避前缀缓存；真实 token 数以服务端 usage 为准。
3. 流式采集 TTFT（首 token 时间）与 TPOT（逐 token 平均间隔）。
4. 请求三分类：A1=失败（HTTP 错误/连接失败/超时/流错误/空输出），A2=成功且 TTFT、TPOT 双双不超出门限，A3=成功但不达标。
5. SLA=(A2+A3)/总数，SLO=A2/总数；随并发递增绘制可用性/质量曲线，陈述两个实测拐点——A3 拐点（质量/SLO 边界）与 A1 拐点（可用性/SLA 边界），SLA/SLO 由此实测产出；人工价值目标（几个 9 的可用性 + 质量达标率）只用于筛选达标前缀（连续前缀规则），并以两者同时达标的**质量容量**作为生产并发建议基准。
6. 每级判定水位状态（服务端水位的黑盒投影，见 docs/05-watermark.md）：NORMAL（无信号）/ BUSY（软水位投影：A3 占比或 TTFT p99 超软门限，服务在排队）/ OVERLOAD（硬水位投影：出现失败——服务端拒绝或客户端超时（Router 无限队列时过载只投影为超时）——或 A3 占比超硬门限）；跨级汇总软/硬/SLA 三个水位边界，分别对应 Router 的排队预警线、熔断线与生产并发建议。
7. 闭环低压级别的样本产出受单请求 E2E 限制，测量段样本不足时本级自动延长（上限 load.max_stage_duration_s；基线阶段按“最短长度桶”判定，因为门限是按桶解析的）；本级结束时仍在途的请求记为放弃（aborted），不计入比率。

## 八、请求特征覆盖

- 计划 prompt 长度分布（token）：[4096]（权重 [1.0]）
- 计划输出长度分布（token）：[128, 256]（权重 [0.7, 0.3]）
- 上下文上限假设：32768 token
- 实测平均 prompt token（全部成功请求按级加权）：1000（计划 4096，偏差 -75.6%）
- ⚠️ prompt 长度偏差超过 15%：requests.chars_per_token=3.5 与服务端 tokenizer 不符，建议校准为 ≈14.34 后复测，否则长度分布未按预期覆盖。
- 实测平均输出 token（全部成功请求按级加权）：80（计划 166）

## 十、建议

- 失败请求（A1）共 30 条，主要构成：http_5xx×30。
- A3（成功但不满足 SLO）共 2 条：TTFT 超标 0 条、TPOT 超标 0 条、双超标 0 条。
- TTFT 与 TPOT 相关超标数量相当：需同时治理排队与 decode 吞吐，或复核两项门限设定。
- 复测建议：固定并发 8 做 30 分钟以上长稳验证，确认指标不随时间漂移；并按请求特征覆盖一节的长度分布核对生产流量特征是否被覆盖。
- 门限来源提醒：本次为 absolute 口径（固定门限），适合作为业务验收契约；若需自动适配不同引擎/模型规模，可改用 slo.target_mode=baseline_relative。
- 水位运维建议：硬水位投影出现在并发 32（服务端拒绝：A1=30/60，拒绝族 30 条）。建议将 Router 拒绝阈值/熔断线设在该并发之下并预留余量；治理方向为扩容 PD 副本或提高准入并发，而非单纯调高拒绝阈值。
- 口径提醒：本报告的 SLA/SLO 为全请求口径（含被拒绝或客户端超时的 A1）；若需“成功请求口径”的时延分布，可查询 DB 中 status='ok' 的明细。

## 附录 B：数据库字段说明

- `stages`：每级压力的配置与聚合结果（SLA/SLO/分位数/吞吐/水位状态）。`kind='stage'` 为正式压力级，`kind='baseline'` 为 Phase 0 基线级（不参与容量判定）。
- `requests`：逐请求特征（长度、TTFT/TPOT/E2E、分类、失败类型），**不含原始请求与响应内容**。
- `stage_buckets`：每级按 prompt 长度桶的拆分（A2/A3/超标归因/该桶生效门限）。
- `baseline`：Phase 0 各长度桶的时延分位数，是 baseline_relative 门限的来源。
- `stages.watermark_state` / `watermark_reasons_json`：本级水位状态（NORMAL/BUSY/OVERLOAD/unknown）与触发原因——服务端水位的黑盒投影，见 docs/05-watermark.md；`--report-only` 会按当前 `[watermark]` 配置重算。
- `is_warmup=1` 的为预热数据，统计时排除。
- `status='aborted'` 的为本级结束时仍在途、超过 drain 上限被放弃的请求，不计入 SLA/SLO 分母。

原始数据库：`results/golden.db`
